### MCP 细节与边界

- 上游 #15714 的 PR 说明与实际补丁不完全一致：不能仅凭说明宣称已阻止未解析占位符。此次在构建 HTTP/SSE client 时使用安装模板同一个解析器，真实本地 HTTP 服务测试断言收到请求数为零。
- `Authorization`、`X-Api-Key`、`Api-Key` 非空且返回 401、没有 `resource_metadata` challenge 时，返回“凭据被拒绝”，不误导用户去做交互式 OAuth。认证头名不区分大小写，重复 challenge 头均检查，带引号的描述文本不冒充参数名。
- 没有静态凭据的 401 仍保留既有 OAuth 流；无界面模式需要交互认证时返回专门的类型化错误，不引导到 Warp 私有云。
- 模板变量中的显式密钥引用返回排序去重的缺失名称；AgentDriver 在启动临时 MCP 之前拒绝缺失值。错误日志不输出头值或密钥值。
- 安全边界是保守拒绝：静态头值中合法但包含 `{{name}}` 的字面量也会被视为未解析模板并拒绝；普通 JSON 大括号不受影响。
- 初次全局配置解析以代际编号过滤过期回调；旧任务的完成回调不能清除新任务或提前关闭扫描。解析失败、缺失和移除均能结束本轮扫描，不导致永久等待。
- 全局扫描与服务器就绪共享 20 秒预算；只等待初次扫描实际请求自动启动的服务器。失败、停止、移除或超时不升级为 Agent 运行失败，超时后清理订阅。晚创建的 Agent 读取已保存的完成快照。
- 本地 `agent_sdk::driver` 是活跃模块，调用在原生 Oz harness 首个 `execute_run` 前；没有把补丁仅套到停挂文件上。

### 为什么不直接升级 winit

本地依赖固定在 `chenx-dust/winit@7ef914a440ad203da05355e6c3f8c482766987ec`，包含 Windows 从注册表读取暗色模式的修复。上游候选实际指向 [`warpdotdev/winit@14db95a`](https://github.com/warpdotdev/winit/commit/14db95a686387211d57cf2afd1d908b2d82a20fe)；两个分支各独有一个提交，整体换 pin 会丢失 Windows 修复。因此不修改依赖源、不改 Cargo 缓存、不创建或推送第三方 fork，而在现有本地 X11 适配层移植相同的“尽力提醒、不因连接错误崩溃”语义。
